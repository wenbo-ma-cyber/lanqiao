# 蓝桥算法星图

一个面向 2027 蓝桥杯 Python 大学 B 组的个人学习网站。采用暖白、鼠尾草绿与香槟金的浅色配色。首页回答“我学到哪了”和“下一步做什么”；刷题和评测在洛谷进行。

## 开始使用

在当前工作区运行：

```bash
python3 -m http.server 8768 --bind 127.0.0.1 --directory output
```

打开 <http://127.0.0.1:8768/lanqiao-learning/>。若该端口已有本任务的预览服务，无需重复启动。不要直接双击 HTML：Three.js 使用 ES module，需要 HTTP 服务。

从发布压缩包开始时，解压，在包含 `index.html` 的目录运行：

```bash
python3 -m http.server 8768 --bind 127.0.0.1
```

然后打开 <http://127.0.0.1:8768/>。没有构建或 npm 安装步骤。

## 每天怎样用

1. 看首页的下一步建议，进入学习主题，先理解目标、要点和常见错误。
2. 点击洛谷题目链接，在洛谷编写、提交和验证。
3. 回来记结果：独立完成、提示后完成、题解后完成或未完成。耗时可留空，题号可之后补充。
4. 按验收要求手动调整状态：未开始 → 学习中 → 待验证 → 已掌握；忘记或反复出错时改为需巩固。
5. 到期复习先独立重做，再点“记录复习”。保存复习结果不会自动判定已掌握。
6. 每周导出一次 JSON 备份。它包含学习记录与私人笔记，保存在自己的设备中。

代码示例默认折叠；排序、二分、BFS、0/1 背包可单步查看。关闭动画仍可单步。没有网页代码执行器或在线判题器。

## 内容与进度规则

- 36 周、7 阶段，共 47 个学习主题：36 个知识主题、11 个整卷与复盘主题。
- 36 道不同洛谷题作为精选练习入口，覆盖入门到进阶；这不是完整的 150～220 道训练配额。可在记录中添加其他洛谷题号、链接或试卷名，重做不应计作新题。
- 每个主题包含目标、概念、例子、常见错误、验收、先修和补充资料。课程全部可查看，不强制锁课。
- 下一步顺序：已到期复习 → 当前阶段标记的薄弱主题 → 正在学习/待验证主题 → 先修已掌握的新主题。日历不会强制推进。
- “已掌握”完全由本人核对验收后确认，不由浏览时长、提交记录或题数自动推断。模拟主题的“已掌握”表示该次测评和复盘验收完成。
- 练习生成隔天和一周后的复习；同主题同一到期日去重。复习记录本身不再无限创建下一轮提醒。编辑日志不移动已有复习日期。
- “独立完成的洛谷题”从独立完成日志的题号中提取并去重，统计依赖手动填写；没有题号的记录不会增加此数。不同结果不会从历史独立完成数中扣除，近期失误可在薄弱点复核。
- 本周投入按当地自然周（周一至周日）累计填写的分钟；空耗时单独显示，不等于 0 分钟。
- 默认 2026-09-28 开始、每周 10 小时。日期与投入可改；2027 赛期未在本计划中确认，按官方通知调整。路线进度不等于获奖概率或官方分数线。
- 较早真题用来学专题，最近可获得的省赛、国赛各 3 套留作陌生整卷。高难度洛谷题是挑战任务，页面核验不等于 Python 在该题的全数据性能保证。

## 数据保存与恢复

网站为纯静态前端，状态通过 `localStorage` 保存在当前浏览器。独立键为 `lanqiao-learning-state-v1`；不读取 DCA 网站的键，也不读取洛谷账号、Cookie 或提交历史。

同一浏览器、相同协议/主机/端口的状态可恢复。`localhost`、`127.0.0.1`、不同端口、GitHub Pages 与其他设备分别保存。换地址或设备时，先在旧页面导出，再在新页面“数据与备份”中导入。

导入流程为选择文件 → 校验 → 查看记录数量 → 确认覆盖。导入是完整替换，不自动合并。支持 v1 JSON，文件最大 5 MB；无效版本、知识点、日期、重复 ID 或非法字段会拒绝导入。清除浏览器网站数据或无痕窗口关闭可能丢失记录，浏览器本地存储不是云备份。

存储失败时页面保留当前内存输入并提示导出；旧数据损坏时暂停覆盖，提供原始存储下载。发现另一标签页改动时暂停保存，避免静默覆盖；先导出当前输入再重新加载。

## 发布到独立 GitHub Pages 网站

交付时没有创建仓库、推送或发布。`蓝桥算法星图-GitHub-Pages.zip` 内是可直接部署的静态文件，不含测试数据或私人笔记。

1. 新建独立仓库，例如 `lanqiao-learning`，避免覆盖原 `DCA-learning`。
2. 解压发布包，把其内容放到仓库根目录，确保根目录直接包含 `index.html`，保留 `.nojekyll` 和 `assets/`。
3. 在仓库 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**，选择已提交文件的分支和 **/(root)**，保存。
4. 等待 Pages 部署成功，使用设置页显示的正式地址。进入后导入自己的学习备份。

上述设置依据 [GitHub Pages 官方发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。不要将导出的学习备份上传到公开仓库。

资源使用相对路径，页面使用 hash 路由，可部署于仓库子路径；没有服务端、密钥、外部字体或 CDN 运行依赖。外部资料和洛谷仍需要联网。没有 Service Worker 离线缓存。

## 维护与验证

| 文件 | 用途 |
| --- | --- |
| `index.html`、`styles.css` | 页面骨架、响应式样式 |
| `curriculum.js` | 36 周课程与精选题目 |
| `core.js` | 推荐、统计、日期、复习、导入校验 |
| `app.js` | 界面、路由、记录、保存与备份 |
| `starfield.js` | Three.js 学习星图；后台与不可见时停止连续绘制 |
| `demos.js`、`demos.css` | 四种辅助算法演示 |
| `assets/vendor/` | Three.js 0.180.0 与 MIT 许可证 |
| `tests/` | Node 内置测试，无第三方测试依赖 |
| `验收记录.md` | 已执行检查和验证边界 |

测试位于本地源码目录，纯静态发布包不包含测试文件。在工作区根目录执行：

```bash
timeout 60 node --test output/lanqiao-learning/tests/*.test.cjs
```

课程主题的 `k01` 等 ID 已用于存储。当前按课程创建顺序分配，发布后修改内容应保持原有 ID；不要直接在中间插入主题或重新排序导致旧 ID 指向别的知识。要调整结构时先改为显式固定 ID，并设计数据迁移和版本升级。

WebGL 不可用时首页保留 36 个文字周次入口；手机可使用文字路线，3D 不影响记录功能。动效同时服从站点开关与系统减少动画偏好。
